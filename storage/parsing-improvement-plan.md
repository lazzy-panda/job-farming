# План улучшения парсинга вакансий

## 1. Обогащение сырого контента
- Расширить `scripts/fetch-missing-raw-content.js`:
  - устойчивые ретраи (403, 302/301) + переключение UA/cookie/прокси;
  - поддержка доменных cookie-пулов (adzuna, talent, indeed, highered) с ротацией;
  - логирование попыток (proxyId, UA, статус) и метрик успеха.
- Массовый докачивающий скрипт: проход по топ-источникам (adzuna/indeed/talent/highered) с параллельной очередью и rate-limit.
- На этапе загрузки RSS/API: если `description` короткий — подтягивать HTML по `link` и сохранять `rawContent` сразу.

## 2. Прокси и куки
- Импорт валидных SOCKS5/резидентных прокси из ручного файла/URL, жёсткая валидация `host:port`.
- Ротация доменных cookie-пулов, обновление «живых» куков для защищённых доменов (Adzuna/Talent/Indeed/HigherEd).
- Авто-деактивация прокси с серией 403/ECONNRESET/ENETUNREACH.

## 3. Парсер title/company
- Ограничить «слипшиеся» регексы концом строки в `extractors/title.ts` и `company.ts`.
- Добавить белый список технологических токенов (TypeScript, DevOps, NestJS и др.), чтобы не считались названиями компаний.
- Дополнить тесты: `title.spec.ts`, `company.spec.ts`, `fixtures.spec.ts` (CamelCase/техтокены).

## 4. Извлечение текста вакансии
- В `JobPostingsService` при парсе RSS/API: если нет `rawContent`, сначала докачать HTML, затем парсить.
- В `analyze-rss-parsing-issues.js`: при нехватке текста подтягивать страницу, сохранять `rawContent` (опционально) и включать в отчёт.
- Фильтрация HTML-шаблонов/редиректов, нормализация текста (без скриптов/баннеров).

## 5. Аудит и метрики
- Расширить отчёт `analyze-rss-parsing-issues.js`/`storage/rss-parsing-issues.md`: доля заполненных полей (title/company/salary/location) и предупреждений по источникам.
- Снимать статистику по БД: количество `rawContent >= 200`, доля успешных парсов по источнику, топ проблемных доменов.

## 6. Чистка и перезапись
- После докачки/парсинга перезаписывать `description/rawContent` для старых записей.
- Помечать безнадёжные (много 403/редиректов) для повторных попыток позже или удаления.

## 7. Проверки и тесты
- Прогон `npx nx test vacancy-parser` после правок регексов/белых списков.
- Регулярный запуск докачки (batched) и обновление отчётов в `storage/rss-parsing-issues.md`.

## 8. Улучшения распознавания/очистки текста
- В `sanitize-input.ts` добавить агрессивное удаление навигации/футеров, а также детект темплейтов (например, Indeed redirect page) с повторным фетчем.
- Для RSS/API добавить эвристику stub-страниц: если `rawContent` < 500 символов или содержит слишком много ссылок/«click here», ставить флаг `needsRefetch`.
- При парсе HTML использовать `readability`-подобный алгоритм: выбирать самый длинный блок текста, удалять inline-скрипты/стили.

## 9. Специализированные коннекторы
- Для защищённых доменов (Adzuna/Talent/Indeed/HigherEd) завести файл cookie-пула + отдельные списки рабочих SOCKS5; в коде коннекторов переключать наборы.
- Для API-источников (Remotive, Arbeitnow, TheMuse, RemoteOK, Jobicy, Findwork, DevITjobsUK) добавить нормализацию схемы и фильтр «младше 14 дней».

## 10. Логирование/наблюдаемость
- В `JobPostingsService` логировать источник + прокси/UA + длину текста, писать счётчики успешных/проваленных парсов в Prometheus-совместимый формат.
- Добавить алерт/отчёт по топ-источникам с процентом пустых вакансий и числом повторных фетчей.

## 11. UI/диагностика
- В админке источников показать метрики: последний успешный парс, доля успехов, наличие `rawContent`.
- Для карточек вакансий добавить индикатор «текст из HTML/описания/стуб» и кнопку ручного рефетча (очередь задачи + рестарт парсинга).
